# Obsidian Task Organizer (AOTO)

전날 생각나는 대로 적어 둔 메모와 할 일을 Gemini API 로 정리해 Obsidian 데일리 노트(`.md`)로 만들고, Obsidian 보관소(Vault)에 바로 저장하는 웹 앱입니다.

- 사이트: https://organizer-eta-beryl.vercel.app (아이디와 비밀번호만 정하면 누구나 가입할 수 있습니다)
- Vercel 에 배포해서 씁니다. 여러 사람이 각자 계정으로 로그인합니다.
- Gemini API 키와 설정(고정 일정, 유동 일정, 저장 위치)은 **사람마다 따로 서버에 저장**됩니다. 한 번 저장하면 그 사람이 로그인한 모든 기기(PC, iPhone)에서 같은 설정이 보이고, 직접 바꿀 때까지 유지됩니다.
- 보관소(Vault)는 Obsidian 이 노트를 모아 두는 폴더를 말합니다.

---

## 무엇을 해 주나

입력 예시(메모를 적는 칸에 그대로 적은 것):

```
- 오후 2시 연구실 가기 전에 과제 피드백 반영하기
- 연구실에서 학회 논문 수정본 작성
- 저녁 8시 헬스장
- 마트 들러서 우유 사가기
```

결과(보관소에 `Daily Notes/2026-11/2026-11-02.md` 로 저장되는 내용의 형태. 항목 문장은 Gemini 가 매번 새로 쓰므로 실제와 다를 수 있음):

```markdown
---
date: 2026-11-02
tags: [daily-notes, task-organizer, scheduler]
status: organized
---

## 주요일정
- [ ] 09:00 컴퓨터 구조 수업        <- 설정해 둔 월요일 고정 일정

## 연구실
- [ ] 오후 2시 과제 피드백 반영
- [ ] 학회 논문 수정본 작성

## 기타
- [ ] 저녁 8시 헬스장
- [ ] 마트에서 우유 사기
```

정리 규칙:

| 칸 | 들어가는 것 |
|---|---|
| 주요일정 | 설정해 둔 **요일별 고정 일정**과, **이번 주 유동 일정** 중 그 날짜 요일에 해당하는 것 |
| 학교 | 메모에 `학교` 또는 `졸작` 이라는 낱말이 있는 항목만 |
| 연구실 | 그 밖의 공부·과제·논문·코딩·미팅 등 학업과 연구 항목 전부 |
| 기타 | 운동, 장보기, 개인 약속 같은 일상 항목 |

그 밖의 동작:

- 결과에 이모지와 큰 제목(`#`)은 넣지 않습니다. 모든 항목은 Obsidian 체크박스(`- [ ]`)입니다.
- 미리보기에서 체크박스를 누르면 마크다운 원본의 `- [ ]` 와 `- [x]` 도 같이 바뀝니다. **마크다운 코드** 탭에서 원본을 직접 고칠 수도 있습니다.
- 같은 날짜 노트가 보관소에 이미 있으면 **불러와서 합치기**가 뜹니다. 누르고 새 메모를 적은 뒤 정리하면, 이미 체크한 항목(`- [x]`)은 그대로 두고 새 할 일만 더합니다. 합칠 때는 고정·유동 일정을 다시 넣지 않고 기존 노트에 있는 것을 그대로 둡니다. (PC Chrome·Edge 에서만, 아래 저장 방식 1)

## 사용 방법

1. 사이트에 들어가면 로그인 화면이 뜹니다. 처음이면 **가입** 탭에서 아이디와 비밀번호(8자 이상)를 정해 가입합니다. 가입하면 바로 로그인됩니다.
2. 가입하면 설정 창이 열립니다. [Google AI Studio](https://aistudio.google.com/app/apikey) 에서 받은 **Gemini API 키**를 넣고 저장합니다. 상단 표시가 `API Key 연결됨` 으로 바뀌면 됩니다.
3. 저장 위치를 정합니다(브라우저에 따라 다름, 아래 표).
   - PC Chrome·Edge: 설정 창의 **Vault 폴더 선택** 버튼으로 보관소 폴더를 고릅니다.
   - iPhone Safari 등: 설정 창의 **Obsidian Vault 이름** 에 Obsidian 앱에 보이는 보관소 이름을 그대로 적습니다.
   - 두 경우 모두 **하위 폴더**(기본 `Daily Notes`)에 데일리 노트를 모아 둘 폴더 이름을 적습니다. 비우면 보관소 맨 위에 저장합니다.
4. (선택) **고정 일정 관리** 에 요일별 수업·세미나를, **이번주 유동 일정** 에 주마다 바뀌는 근무표 문자 같은 것을 통째로 붙여 둡니다.
5. 날짜(오늘, 내일, 직접 선택)를 고르고 메모를 적은 뒤 **AI로 하루 일정 정리하기** 를 누릅니다. 생성에는 수 초에서 십수 초가 걸립니다.
6. 결과를 확인하고 **Obsidian 보관소에 저장** 을 누릅니다. **.md 파일 받기**, **클립보드 복사** 도 쓸 수 있습니다.

## 저장 방식: 브라우저에 따라 둘로 나뉩니다

브라우저가 내 컴퓨터 폴더에 직접 쓸 수 있는지(File System Access API 지원 여부)에 따라 앱이 자동으로 고릅니다.

| | 1. 폴더 직접 저장 | 2. Obsidian 앱 링크 |
|---|---|---|
| 브라우저 | PC 의 Chrome, Edge | iPhone Safari, Firefox 등 위 둘을 뺀 전부 |
| 동작 | 고른 보관소 폴더에 파일을 직접 쓰고 읽음 | 저장 버튼을 누르면 `obsidian://new` 링크로 Obsidian 앱이 열리고 노트가 만들어짐 |
| 필요한 설정 | Vault 폴더 선택 | Vault 이름 |
| 저장 경로 | `[하위 폴더]/YYYY-MM/YYYY-MM-DD.md` | 같음 |
| 같은 날짜 노트가 있을 때 | **불러와서 합치기** 가능 | 덮어씀(합치기 불가) |
| 다시 방문할 때 | Chrome 이 폴더 접근 허용을 물을 수 있음. "방문할 때마다 허용"을 고르면 다음부터 묻지 않음 | 추가 동작 없음 |

iCloud Drive 에 둔 보관소라면, PC 에서는 방식 1로 `iCloud Drive/Obsidian/[보관소 이름]` 폴더를 고르고, iPhone 에서는 방식 2로 같은 보관소 이름을 적으면 됩니다.

## 계정과 보안

| 무엇 | 어디에 저장 | 비고 |
|---|---|---|
| 아이디, 비밀번호 | 서버(Upstash Redis) | 비밀번호는 scrypt 해시만 저장, 원문은 저장하지 않음 |
| Gemini API 키 | 서버, 아이디별 | 브라우저로 내려보내지 않음. 생성 요청은 서버(`/api/generate`)가 그 사람의 키로 Gemini 에 보냄 |
| 고정·유동 일정, Vault 이름, 하위 폴더 | 서버, 아이디별 | 그 사람이 로그인한 모든 기기에 같게 적용 |
| Vault 폴더 접근 권한(방식 1) | 그 브라우저 안(IndexedDB), 아이디별 | 브라우저 보안 규칙상 서버에 둘 수 없음. 브라우저마다 한 번 고름 |
| 로그인 상태 | 브라우저 쿠키(HttpOnly, 서명됨) | 365일 유지, 로그아웃 버튼으로 끝냄 |

- 아이디는 영문 소문자, 숫자, `_`, `-` 로 3~20자입니다.
- 가입은 열려 있어 사이트 주소를 아는 누구나 할 수 있습니다. 각자 자기 Gemini API 키를 넣어 쓰므로 다른 사람의 사용량이 내 키로 나가지는 않습니다.
- 자동 프로그램이 계정을 대량으로 만들지 못하도록, 같은 IP 에서는 1시간에 5개까지만 가입됩니다.
- 같은 IP 에서 로그인 비밀번호를 10번 틀리면 그 IP 는 15분 동안 로그인이 막힙니다.
- 설정 창의 API 키 칸은 저장 뒤 비어 보입니다. 비워 둔 채 저장하면 저장된 키를 그대로 쓰고, 새 키를 적고 저장하면 바뀝니다.
- 같은 브라우저에서 로그아웃하고 다른 사람이 로그인하면, 앞사람의 메모·결과·설정·Vault 폴더는 화면에서 모두 비워집니다.

## 배포 (Vercel)

1. Vercel 에서 **Add New > Project** 로 이 저장소를 가져옵니다. Framework Preset 은 **Other** 그대로 둡니다. 빌드 단계는 없고, `vercel.json` 이 `public/` 을 화면으로, `api/` 를 서버 함수로 배포합니다.
2. 프로젝트의 **Storage** 탭에서 **Upstash (Redis)** 를 만들고 이 프로젝트에 연결합니다.
   - Primary Region 은 `us-east-1` 을 고릅니다. Redis 에 접속하는 쪽은 브라우저가 아니라 Vercel 서버 함수이고, Vercel 무료 요금제의 함수 기본 지역이 `iad1`(미국 워싱턴 D.C.)이기 때문입니다.
   - 연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN` 환경 변수가 자동으로 들어갑니다.
   - 저장하는 것은 사용자 한 명당 키 두 개(계정 하나, 설정 하나), IP 별 로그인 실패 횟수(15분 뒤 지워짐)와 가입 횟수(1시간 뒤 지워짐), 로그인 쿠키 서명 키 하나입니다.
3. 환경 변수는 새 배포부터 적용됩니다. Upstash 를 연결한 뒤에는 **Deployments** 에서 최신 배포를 **Redeploy** 합니다.
4. 사이트에 들어가 **가입** 탭에서 계정을 만듭니다.

이후 `main` 브랜치에 push 하면 Vercel 이 자동으로 다시 배포합니다.

### 환경 변수

| 이름 | 필수 | 내용 |
|---|---|---|
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | 필수 | Upstash 연결 시 자동 입력. `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` 이름도 인식 |
| `GEMINI_MODEL` | 선택 | 쓸 Gemini 모델 이름. 비우면 `gemini-3.8-flash` |
| `SESSION_SECRET` | 선택 | 로그인 쿠키 서명 키. 비우면 처음 쓸 때 무작위 값을 만들어 Redis 에 보관. 값을 바꾸면 모든 기기가 로그아웃됨 |

## 문제 해결

화면 오른쪽 아래 빨간 알림에 뜨는 문구로 원인을 가릅니다.

| 알림 문구 | 원인 | 해결 |
|---|---|---|
| `Gemini API 오류 (404) ... gemini-2.5-flash is no longer available to new users` | Google 이 이 모델을 새로 발급한 키에 막음 | 이 저장소는 `gemini-3.8-flash` 를 쓰도록 이미 바뀌어 있음. `GEMINI_MODEL` 에 2.5 를 넣었다면 지움 |
| `Gemini API 오류 (403) The Gemini API free tier is not available for this project` | 그 키가 속한 Google 프로젝트가 무료 사용 대상이 아님(Google 이 프로젝트 단위로 판단). 같은 프로젝트에서 키를 새로 만들어도 같음 | [AI Studio 결제 페이지](https://aistudio.google.com/billing)에서 결제 계정을 연결. 사용한 만큼 요금이 나가므로 Google Cloud Billing 에 예산 알림을 걸어 두기를 권함 |
| `Gemini API 오류 (400) API key not valid` | 키를 잘못 넣음 | 설정 창에 키를 다시 넣고 저장 |
| `Gemini 응답이 길이 한도에 걸려 비어 있습니다` | 모델이 생각하는 데 응답 한도(16,384 토큰)를 다 씀 | 메모를 나눠서 다시 정리 |
| `저장소(Upstash Redis)가 연결되지 않았습니다` | Upstash 가 프로젝트에 연결되지 않음 | 배포 2단계를 하고 Redeploy |
| `이 네트워크에서 가입이 많아 1시간 동안 가입이 막혔습니다` | 같은 IP 에서 1시간 안에 5개를 가입함 | 1시간 뒤 다시 시도 |
| `실패가 많아 15분 동안 잠겼습니다` | 같은 IP 에서 10번 틀림 | 15분 뒤 다시 시도 |
| `Vault 권한 필요 (클릭)` (상단 표시) | 브라우저를 다시 열어 폴더 접근 허용이 풀림 | 그 표시를 눌러 허용 |

## 폴더 구조

```
public/            화면 (정적 파일)
  index.html       화면 구성, 로그인·설정 창
  app.js           화면 동작: 로그인, 설정, 생성 요청, 보관소 저장(폴더 직접 저장 / obsidian:// 링크)
  style.css
api/               Vercel 서버 함수 (주소 /api/<파일 이름>)
  signup.js        가입 (아이디·비밀번호 확인, 계정 생성, IP 별 가입 횟수 제한)
  login.js         로그인
  logout.js        로그아웃
  session.js       로그인 상태 확인
  config.js        내 설정 읽기·저장 (API 키는 읽기 응답에 넣지 않음)
  generate.js      내 설정과 키로 Gemini 호출
lib/               서버 함수가 함께 쓰는 코드
  http.js          요청·응답 처리, 비밀번호 해시, 로그인 쿠키, 실패 횟수 제한
  store.js         Upstash Redis 접근 (REST API)
  gemini.js        Gemini 프롬프트와 호출
vercel.json        배포 설정 (public/ 출력, 보안 헤더, 생성 함수 최대 60초)
```

## 로컬 실행

```bash
npm run dev
```

Vercel CLI(`vercel dev`)로 화면과 `/api` 함수를 함께 띄웁니다. 처음에는 Vercel 로그인과 프로젝트 연결을 묻습니다.

- 배포 환경의 환경 변수는 `vercel env pull` 로 받을 수 있습니다. 받은 `.env` 파일은 `.gitignore` 에 들어 있어 커밋되지 않습니다.
- Redis 환경 변수가 없으면 로컬에서는 메모리에 저장하고, 서버를 끄면 지워집니다. Vercel 에 배포된 환경(Production, Preview)에서는 Redis 가 없으면 오류를 냅니다.
- 폴더 직접 저장(방식 1)은 `https://` 주소나 `localhost` 에서만 동작합니다.
